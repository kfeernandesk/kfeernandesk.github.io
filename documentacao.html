01 / VISÃO GERAL

O que é o LoopingBR Publisher?

Um aplicativo desktop independente criado para organizar o processo de publicação de vídeos e Shorts no YouTube. A edição híbrida combina uma interface local Windows, um backend local para autenticação, automação via GitHub Actions e integração com APIs oficiais quando as contas são autorizadas.

O projeto nasceu de uma necessidade prática de produção de conteúdo: reunir seleção de arquivos, revisão de dados, envio e acompanhamento em um fluxo mais fácil de operar. O sistema usa recursos de IA como apoio opcional, mas não transfere para a IA a decisão de publicar.

Versão documentada: v1.0.14.1, edição de laboratório e portfólio. O código-fonte pode ser estudado e compilado; integração real depende de credenciais, rede e permissões próprias.

02 / CAPACIDADES

Recursos principais

  • Fluxo guiado de publicação: configurações iniciais, seleção do conteúdo, metadados, revisão e confirmação.
  • Vídeos e Shorts: título, descrição, visibilidade, classificação de público, thumbnails e agendamento conforme restrições de cada serviço.
  • Arquivos locais e Google Drive: alternativas de origem de mídia de acordo com a configuração.
  • GitHub Actions: processamento de pedidos de publicação aprovados, com rastreabilidade de estados.
  • Histórico e métricas: consulta ao andamento dos pedidos e dados do YouTube Analytics quando disponíveis.
  • Assistência de IA: apoio opcional a textos, rascunhos e interpretação cuidadosa de informações.
  • LoopingBR Studio: fluxo separado para conceitos de thumbnails, referências e refinamento de prompts.

Esses recursos não tornam o aplicativo um serviço hospedado pronto para utilização sem configuração. Cada integração precisa de autorização apropriada.

03 / COMPONENTES

Arquitetura do sistema

ComponenteFunção
Desktop (Go + HTML/CSS/JS)Experiência visual, preparação de pedidos e revisão.
Backend local (Go)Autenticação OAuth, sessões e comunicação com integrações.
GitHub Actions + PythonExecuta o fluxo autorizado e registra resultados.
Google Drive / YouTubeLeitura de mídia e publicação mediante permissões do usuário.
YouTube AnalyticsConsulta opcional de informações disponíveis à conta.
StudioApoio criativo separado, voltado à preparação visual.

Sequência de uma publicação

  1. A pessoa prepara o vídeo e define seus metadados na interface.
  2. O aplicativo apresenta os dados para revisão e confirmação explícita.
  3. O pedido aprovado é registrado no repositório operacional privado apropriado.
  4. O GitHub Actions processa o pedido, usando autorização válida para acesso aos serviços.
  5. O resultado é registrado e pode ser conferido na interface e no YouTube Studio.

Importante: o repositório público de portfólio não é o repositório operacional que deve guardar pedidos reais e dados de conta.

04 / COMEÇANDO

Instalação no Windows

Pré-requisitos

  • Windows 10 ou 11, 64 bits, para o aplicativo compilado.
  • Go 1.23 ou superior para compilar o código.
  • Conta GitHub e projeto Google Cloud próprios para testar integrações reais.
  • Python 3.12 para o executor usado em GitHub Actions; a interface local não exige necessariamente instalação local do Python.

Opção A — baixar a versão compilada

Acesse Releases no GitHub, expanda Assets e baixe o pacote Windows. Extraia todos os arquivos e siga o guia de configuração antes de testar serviços reais.

Opção B — compilar do código-fonte

Clone o repositório ou baixe seu ZIP e, no PowerShell, dentro da pasta apps/publisher-hibrido, execute:

go test ./...
.\GERAR-EXES-LAB.bat

O script foi projetado para gerar os arquivos LoopingBR-Publisher-Hybrid-Desktop-LAB.exe e LoopingBR-Hybrid-Backend-LAB.exe. Esses dois componentes são utilizados no funcionamento local.

05 / INTEGRAÇÕES

Configuração de contas e OAuth

Para operações reais, é necessário habilitar as APIs Google utilizadas no projeto e configurar um cliente OAuth adequado no projeto Google Cloud da pessoa que instalar o aplicativo. A edição híbrida documenta o uso de um cliente OAuth do tipo Aplicativo da Web com URI de redirecionamento local exata:

http://127.0.0.1:8765/oauth/google/callback

O backend local solicita as credenciais no computador e gerencia a autenticação. O primeiro fluxo de integração também envolve a conta GitHub e um repositório operacional privado para tarefas de publicação.

Para execução remota: se o GitHub Actions precisar alcançar um backend local, esse acesso exige configuração específica de rede e um HTTPS seguro. Não exponha livremente o backend na internet.

O site que você está lendo não executa OAuth: não coleta tokens nem substitui o URI de retorno. A alteração deste layout não muda automaticamente o projeto, os escopos ou o estado do aplicativo no Google Cloud.

Para outras formas de operação, consulte o guia completo. Nenhum segredo pessoal acompanha o código ou a versão de portfólio.

06 / VALIDAÇÃO

Primeiro teste seguro

  1. Instale e inicie o backend e o Desktop seguindo o guia.
  2. Confira a conta Google, o canal YouTube autorizado e a integração GitHub.
  3. Utilize um vídeo pequeno e próprio, com visibilidade Não listado.
  4. Revise título, descrição, classificação de público e miniatura.
  5. Confirme o envio conscientemente e acompanhe o resultado no GitHub Actions e no YouTube Studio.

Um pedido criado não garante que o YouTube tenha concluído a publicação. Se o upload for iniciado e o estado ficar incerto, verifique no Studio antes de repetir a operação.

07 / PRIVACIDADE

Segurança por construção e por operação

  • O sistema exige confirmação explícita para publicar.
  • Credenciais e tokens devem permanecer fora dos arquivos públicos.
  • O armazenamento de sessão do aplicativo Windows usa mecanismos de proteção locais descritos no código.
  • O sistema diferencia pedido iniciado, resultado obtido e situações incertas.
  • Os pedidos e dados reais pertencem ao ambiente operacional privado, não ao repositório de portfólio.

Consulte a Política de Privacidade e as notas técnicas de segurança.

08 / TRANSPARÊNCIA

Testes e limitações conhecidas

A versão pública contém testes automatizados e código compilável, mas isso não comprova que todas as integrações funcionem em qualquer máquina. OAuth, permissões, cotas das APIs, conexão HTTPS do backend, comportamento do YouTube e serviços de terceiros devem ser validados no ambiente de instalação.

O módulo histórico integracoes/publicador-classico demonstra uma etapa anterior do projeto e não representa uma cópia integral atualizada do repositório operacional privado.

O projeto permanece em evolução. A documentação evita atribuir resultados de negócio ou garantias de disponibilidade que não foram medidos.
